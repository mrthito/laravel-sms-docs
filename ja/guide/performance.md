# パフォーマンス

<p class="lead">SMS の送信にかかる時間の大半は、プロバイダーの応答待ちです。このパッケージはその時間を無駄にしません。プロバイダーが許す場合はリクエストの数を減らし、許さない場合はリクエストを並列に投げます。</p>

## 一括送信対応のプロバイダー：リクエスト 1 回 {#bulk-providers-one-request}

次のプロバイダーは 1 回の API 呼び出しで多数の宛先を受け付けるので、200 人宛てのメッセージも HTTP リクエスト 1 回で済みます。

**Sinch、Plivo、Infobip、ClickSend、Clickatell、Sparrow SMS、Sendchamp、Africa's Talking、BulkSMS、SendPulse**、そして **MSG91** のテンプレート送信です。

Clickatell は 1 回の呼び出しにつき宛先 100 件までなので、それを超える送信はパッケージが自動的にバッチに分割します。

## 宛先ごとに送るプロバイダー：並列で {#per-recipient-providers-in-parallel}

**Twilio、Vonage、Telnyx、Bird、Brevo、Bandwidth、WhatsApp、Termii**、そして本文のみの **MSG91** は、1 リクエストにつき宛先を 1 件しか受け付けません。パッケージは 1 件ずつ応答を待ってから次を送るのではなく、Laravel の `Http::pool()` を使って並列に送信します。

デフォルトでは 10 件のリクエストを同時に実行します。

```ini [.env]
SMS_HTTP_CONCURRENCY=10
```

プロバイダーとの往復が 1 回あたり 300 ms ほどだとすると、100 件の宛先に送るのにかかる時間は 30 秒ではなく約 3 秒です。大量に送る場合、プロバイダーのレート制限に余裕があればこの数を増やし、`429 Too Many Requests` が出るようなら減らしてください。

Amazon SNS は AWS SDK を通じて、宛先を 1 件ずつ送信します。

## タイムアウト {#timeouts}

```ini [.env]
SMS_HTTP_TIMEOUT=30
SMS_HTTP_CONNECT_TIMEOUT=10
```

接続タイムアウトがあるので、プロバイダーに到達できないときはすぐに失敗します。これが特に効いてくるのが[フェイルオーバー](/ja/guide/failover)チェーンで、固まったまま待ち続けることなく、10 秒後には次のプロバイダーに順番が回ります。

## トークンのキャッシュ {#token-caching}

Bandwidth と SendPulse は OAuth を使います。アクセストークンは Laravel のキャッシュストアを通じて、有効期限の少し前までキャッシュされるので、ほとんどの送信では余分な往復が発生しません。認証情報をローテーションした後などに、プロバイダーが期限前のトークンを拒否した場合は、そのトークンを破棄し、次の送信で新しいトークンを取得します。

## アプリケーション側でできること {#in-your-application}

- **Web リクエスト中の送信はキューに入れる。** [キュー](/ja/guide/queueing)を使えば、ネットワーク待ちをリクエストの外に完全に追い出せます。
- **大量送信には一括送信対応のプロバイダーを使う。** 何百回ものリクエストより、1 回のリクエストのほうがはるかにスケールします。
- **1 バッチには 1 つのメッセージを。** 同じ本文を 500 回別々に送るより、1 つのメッセージを 500 件の番号に送るほうがずっと速く済みます。
